# 我的口袋导游 MVP

这是根据 V1 产品需求搭建的可演示 MVP，包含：

- 原生微信小程序前端
- FastAPI 后端
- SQLite 数据存储
- 本地模拟模式
- 创建行程、需求确认、生成进度、时间轴、地图、动态调整和撤销主链路
- 在途陪伴工作台：手动签到、景点讲解、途中问答、周边服务与系统地图导航

## 目录

```text
pocket-guide-mvp/
├── miniprogram/          微信小程序
├── backend/              FastAPI 服务
├── project.config.json   微信开发者工具项目配置
└── README.md
```

## 启动后端

```powershell
cd backend
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload --port 8000
```

打开 `http://127.0.0.1:8000/docs` 查看接口文档。

## 启动并联调小程序

1. 保持后端服务运行。
2. 打开微信开发者工具，导入本目录 `pocket-guide-mvp`。
3. 使用测试号或自己的 AppID。
4. 在“详情 → 本地设置”中勾选“不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书”。
5. 点击“编译”，然后从首页点击“创建新行程”。

## 配置光墩墩语音

在途陪伴页已接入 `guangdundun-tts` 微信云函数。语音服务未配置或失败时，页面仍会保留完整文字讲解。

1. 在微信开发者工具中开通云开发并创建环境。
2. 如需固定环境，将云环境 ID 填入 `miniprogram/config/runtime.js`；留空则使用开发者工具当前默认环境。
3. 在云开发面板中上传并部署 `cloudfunctions/guangdundun-tts`，运行时选择 Node.js 18 或更高版本，函数超时设置为至少 25 秒。
4. 在云函数环境变量中配置 `AZURE_SPEECH_KEY` 和 `AZURE_SPEECH_REGION`。密钥不得写入小程序、Git 仓库或日志。
5. 在 Azure 创建 Speech 资源后，从“密钥和终结点”页面取得 Key 和 Region。部署完成后，在真机点击景点讲解播放按钮验证声音和口型。

小程序默认连接本地接口 `http://127.0.0.1:8000/api/v1`。联调时可在微信开发者工具的 Network 和 Console 面板查看请求与错误，同时在后端终端查看接口访问日志。

模拟器可直接访问 `127.0.0.1`。真机调试时需要让后端监听 `0.0.0.0`，并将接口地址替换为电脑的局域网 IP；正式发布时需要使用 HTTPS 合法域名。

## 主演示脚本

1. 以游客身份进入首页。
2. 创建“北京四日游”：2 人、预算 3000 元、文化和美食、适中节奏。
3. 确认需求摘要并生成行程。
4. 查看时间轴和地图。
5. 输入“走得有点累，后面少走一点”。
6. 查看减少步行、替换节点和预算变化。
7. 确认应用新方案，或撤销恢复上一版本。

## 当前实现边界

- 地图使用原生 `map` 组件和演示坐标，真实地点检索与路线计算预留后端接口。
- 语音、ASR、TTS 和 GMTalker 目前使用交互占位与降级状态。
- 在途陪伴的语音播放、语音转文字和周边距离目前为明确标注的演示降级；文字问答、签到、动态调整和导航入口可联调。
- 行程规划器为确定性演示规划器，便于比赛现场稳定演示；可在 `backend/app/planner.py` 中替换为 LangGraph 工作流。
- 未实现支付、酒店/票务交易、多人协作、社区和后台持续定位。
